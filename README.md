# RAIM AR 자율주행 · 마커 버전 v0.3.5 + AR(ARCore) 버전 2단계

AI 없이 마커만으로 "도로 정렬 → AR 주행 → 바리케이드 인식 → 감속·정지" 전체 흐름을 확인하는 웹앱이에요.
WebXR·ARCore 없이 일반 카메라(getUserMedia)로 동작하므로 갤럭시 태블릿 Chrome뿐 아니라 노트북에서도 시험할 수 있어요.

| 파일 | 내용 |

## 1. 태블릿에서 여는 방법 (HTTPS 필요)

카메라는 HTTPS 주소에서만 열려요. 파일을 태블릿에서 바로 열면 카메라가 막혀요.

- **Vercel (권장):** 이 저장소 폴더에서 `npx vercel` 실행 → 나온 주소를 태블릿 Chrome에서 열기
- GitHub Pages 등 HTTPS 정적 호스팅이면 어디든 돼요.
- 노트북에서 시험: 같은 폴더에서 `python3 -m http.server` 실행 후 `http://localhost:8000` (localhost는 예외로 카메라 허용)

## 2. 책상에서 시험하기 (A4 테스트 시트)

1. PDF 1쪽을 **실제 크기(100%)**로 인쇄하고, 가운데 선이 정확히 10cm인지 자로 확인해요.
2. 시트를 평평한 책상에 테이프로 고정해요.
3. PDF 2쪽을 인쇄해 미니 바리케이드를 접어 세워요.
4. 앱에서 **카메라 시작** → 시트를 **비스듬히** 비춰요. 처음 몇 초간 카메라 화각을 자동 보정해요(왼쪽 위 `f … (보정 n/20)`).
   정면 위에서 수직으로만 비추면 보정이 잘 안 돼요.
5. 빨간 자동차가 도로를 돌기 시작하면, 바리케이드를 도로를 가로지르게 세워요.
   → 인식 카드에 "바리케이드 보임", 판단 카드에 "경로 위 · 앞 n cm", 제어 카드가 감속 → 정지로 바뀌어요.
6. 바리케이드를 치우면, 그 자리가 화면에 보이는 상태로 2초가 지나면 해제되고 다시 출발해요.
   (화면 밖에 있으면 "기억 중"으로 유지해요. 바로 해제하려면 **바리케이드 해제** 버튼.)

## 3. 디오라마에 적용하기 (줄자 필요 없음)

1. **마커 붙이기:** `RAIM-AR-마커-8cm.pdf`의 도로 마커(0~9, 12~19번)를 디오라마 테두리에 붙여요. **가로 변에 4개씩, 세로 변에 5개씩(모두 18개)**이 기준이에요.
   10·11번은 바리케이드 전용이라 도로에 붙이면 안 돼요.
   위치·방향은 자유예요. 다만 **이웃한 마커 두 개가 태블릿 화면에 함께 들어올 만한 간격**(대략 40~60cm)으로,
   **도로면과 같은 높이에 평평하게** 붙여요. 흰 테두리는 자르지 말고 남겨 두세요.
2. **마커 지도 만들기:** 앱의 **마커 지도 만들기** → 마커 크기 `8` 확인 → 테두리를 따라 천천히 한 바퀴 비춰요.
   - 화면의 마커 색: 파랑 = 기준(원점), 초록 = 등록됨, 주황 = 확인 중
   - 이웃한 마커가 늘 두 개 이상 보이게 하고, 마지막에 처음 마커까지 돌아오면 가장 정확해요.
   - 모두 초록이 되면 **완료·계산**. 1초 정도 계산한 뒤 "정확도 좋음/보통/낮음"을 알려 줘요.
   - 이때 카메라 화각도 함께 보정돼요. A4 테스트 시트에서 처음 넘어올 때만 자동차 크기·속도를 마커 크기 비율로 키워요(3cm → 8cm면 약 2.7배).
     이미 디오라마 지도가 있으면(예: 10cm → 8cm로 다시 만들기) 맞춰 둔 차 크기·속도는 그대로 둬요.
3. **경로 기록:** 지도 저장 후 바로 경로 기록 화면이 열려요.
   - 차가 달릴 **차선 가운데**를 진행 방향대로 탭해요. 대충 찍어도 돼요. 직선은 양 끝만, **곡선은 2~3번**이면 충분해요.
   - 탭하면서 태블릿을 경로를 따라 천천히 움직여 주세요. 이때 보이는 도로를 위에서 본 영상으로 모아요.
   - **차선 맞추기**(초록 버튼) → 탭한 경로를 양쪽 흰 선 사이(어두운 노면)의 가운데로 옮긴 초록 선이 나와요.
     흰 선을 못 찾은 곳(교차로, 점선이 끊긴 곳, 화살표)은 앞뒤에서 이어 붙여요.
   - 초록 선이 괜찮으면 **완료·저장**. 마음에 안 들면 **되돌리기**(초록 선만 지움) 후 탭을 고치고 다시 맞춰요.
   - "덜 비췄어요"가 나오면 탭한 곳을 따라 한 번 더 천천히 비춘 뒤 다시 눌러요.
   - 차선 폭은 영상에서 자동으로 재요. 잘 안 맞으면 설정의 `lane.width`에 실제 차선 폭(cm, 흰 선 안쪽끼리)을 적어요.
4. **바리케이드:** 마커 10을 레고 바리케이드 패널 앞면 가운데에, 11을 뒷면 가운데에 붙이고(화살표가 하늘 쪽),
   설정에서 `barricade.width`를 바리케이드가 바닥에서 도로를 막는 실제 폭(cm)으로 바꿔요.
5. 차 크기는 오른쪽 **차 − / 차 +** 버튼으로 바로 조절해요(누를 때마다 1.25배, 설정의 `car.scale`에 저장).
   속도는 **속도 − / 속도 +** 버튼으로 조절해요(누를 때마다 1.25배, `drive.speedScale`에 저장).
   빨라져도 감속 시작 거리와 감속도를 같은 비율로 늘려서 바리케이드 앞에서 똑같이 멈춰요.
   기본값 자체는 설정의 `drive`에서 바꿀 수 있어요 (단위 cm, cm/s).
6. **도로 높이:** 마커를 붙인 면과 도로 면 높이가 다르면(예: 마커는 테이블, 도로는 레고 판 위) 차가 떠 보이거나 파묻혀 보이고,
   휴대폰을 움직이면 차가 도로 위에서 미끄러지듯 따라와요. **높이 − / 높이 +**로 맞춰요(한 번에 마커 크기의 1/40, 8cm 마커면 0.2cm).
   - 차가 떠 보이면 −, 파묻혀 보이면 + 쪽이에요. 자로 잰 높이 차이에서 시작하면 빨라요.
   - 맞추는 법: 휴대폰을 좌우로 움직여 봐서 **파란 경로선이 차선에서 미끄러지지 않고 붙어 있으면** 맞은 거예요.
   - 경로 탭과 차선 맞추기도 이 높이의 면을 기준으로 계산해요. 높이를 바꾸기 전에 기록한 경로는 조금 어긋날 수 있으니 **경로 기록을 다시** 해 주세요.

마커를 떼었다 다시 붙이거나 옮기면 **마커 지도 만들기 → 경로 기록**을 다시 하면 돼요.
설정은 그 태블릿의 브라우저에만 저장돼요. 여러 태블릿이 같은 지도·경로를 쓰려면 아래처럼 전시 설정을 올려요.

### 여러 태블릿이 같은 경로 쓰기 (전시 설정)

마커 지도와 경로는 "디오라마 기준 좌표"라서, 한 기기에서 만든 것을 다른 기기에 그대로 쓸 수 있어요.

1. 한 기기에서 **마커 지도 만들기 → 경로 기록(차선 맞추기)**까지 마치고, 차 크기·속도·도로 높이도 맞춰요.
2. **전시 설정 내보내기**를 눌러 `diorama.json`을 받아요. (마커 버전: 설정 화면 / AR 버전: 시작 화면)
3. 이 파일을 저장소 맨 위 폴더에 올려요(GitHub 웹에서 *Add file → Upload files*, 또는 Claude에게 파일 내용을 보내 올려 달라고 하기). Vercel이 다시 배포하면 끝.
4. 모든 기기가 앱을 열 때 자동으로 불러와요. 시작 화면에 "전시 설정(날짜 저장)을 불러왔어요"가 떠요.

- 같은 파일이면 한 번만 불러와요. 그 뒤 기기에서 바꾼 값(예: 차 크기)은 유지되고, **새 파일을 올리면** 모든 기기가 다시 새 값으로 바뀌어요.
- 기기에서 바꾼 값을 버리고 파일 값으로 되돌리려면 **전시 설정 다시 불러오기**.
- 공유하는 것: 마커 지도, 경로, 도로 높이, 차 크기·속도, 바리케이드 폭, 차선 설정. 공유하지 않는 것: 마커 버전의 카메라 화각 보정값(기기마다 카메라가 달라서).
- 마커를 옮기거나 다시 붙이면 지도·경로를 다시 만들고 `diorama.json`도 다시 올려야 해요.

## 4. 현재 한계 (다음 단계에서 해결)

- 마커가 **하나만** 보이면 바닥 기울기가 덜 정확해요(작은 사각형 하나로는 기울기가 잘 정해지지 않음). 가능하면 **2개 이상** 보이게 비춰 주세요.
  화면 위 문구가 "마커가 2개 이상 보이면 더 안정적이에요"로 알려 줘요.
- 휴대폰을 세로로 들면 인식·판단·제어 카드가 한 줄로 작게, 버튼은 그 아래 3열로 나와요. **메뉴 접기**로 버튼을 숨기고 화면을 넓게 쓸 수 있어요.
- 도로 마커가 **하나 이상 화면에 보여야** 자동차가 표시돼요. 마커를 놓치면 0.7초 뒤 숨겨요. (ARCore 버전에서 해결)
- 도로 마커는 한 평면 위에 있어야 해요. 낮은 각도용 세운 마커는 아직 안 돼요.
- 돔·건물·실제 바리케이드에 AR 차가 가려지는 처리(가림 처리)가 없어요. → 아래 'ARCore 버전에서 할 일'의 깊이 기반 가림 처리로 해결할 예정이에요.
- 태블릿 간 바리케이드 공유("모두 멈춤")는 아직 없어요. 지금은 각 태블릿이 자기가 본 바리케이드에만 반응해요.
- 옆에서 끝면을 보면 바리케이드 마커가 안 보여 인식이 안 돼요.
- 차선 맞추기는 "어두운 노면 + 흰 선" 도로를 기준으로 해요. 노면과 선의 밝기 차이가 작거나, 선이 아주 가늘어 화면에서 1픽셀도 안 되면
  (예: A4 시트의 0.8mm 점선) 그 선은 못 보고 도로 전체 폭의 가운데로 맞춰요.
- 탭한 경로가 곡선에서 차선 폭의 절반 넘게 옆 차선으로 들어가면 그 구간은 옆 차선에 맞춰질 수 있어요. 곡선은 2~3번 탭해 주세요.

## 5. AR(ARCore) 버전 사용법 — 1·2단계

갤럭시 휴대폰·태블릿의 **Chrome**에서 `ar.html`을 열어요(마커 버전 시작 화면의 초록 **AR 버전으로 시작** 버튼). 아이패드·노트북은 마커 버전을 써요.
마커 지도·경로·차 크기·속도·도로 높이 설정은 **같은 기기의 마커 버전과 함께** 써요.

1. **처음 한 번:** 마커 버전에서 **마커 지도 만들기**를 해 둬요(AR 버전 시작 화면에 지도 상태가 나와요).
2. **AR 시작** → 카메라 권한 허용 → 디오라마 테두리의 도로 마커를 비춰요. 1~2초면 "위치 맞춤 완료".
   - 화면의 초록 사각형(지도의 마커 위치)이 실제 마커에 겹쳐 보이면 잘 맞은 거예요.
   - 맞춘 뒤에는 **마커가 화면에 없어도 차가 계속 달려요.** 마커를 볼 때마다 위치가 조금씩 더 정확해져요.
   - 디오라마(책상)가 수평이라고 보고, 기울기는 ARCore가 아는 중력 방향을 써요. 그래서 마커가 1개만 보여도 바닥이 들리지 않아요.
3. **경로 기록:** 마커 버전과 같아요. 차선 가운데를 탭 → **차선 맞추기** → **완료·저장**.
4. **높이 자동:** 누른 뒤 3초 동안 도로 위를 비스듬히 비추면 ARCore가 찾은 바닥으로 도로 높이를 재요. **높이 −/+**로 손으로 맞출 수도 있어요.
5. 위치가 어긋났다 싶으면 **다시 맞추기**.
6. **바리케이드(2단계):** 마커 10·11을 붙인 바리케이드를 도로에 세우고 비추면 인식 카드에 "바리케이드 보임",
   경로를 막으면 판단 카드에 "경로 위 · 앞 n cm", 제어 카드가 감속 → 정지로 바뀌어요. 화면에는 바리케이드 자리에 상자가 보여요(노랑: 경로 밖, 빨강: 경로를 막음).
   - 치우면, 그 자리가 화면에 보이는 상태로 2초가 지나면 해제되고 다시 출발해요. 화면 밖에 있으면 "기억 중"으로 유지해요. 바로 해제하려면 **바리케이드 해제**.
   - 바리케이드 마커는 3cm라 대략 **60~80cm 안**에서 인식돼요. 더 멀리서 보려면 마커를 크게 인쇄하고 설정의 `barricade.markerSize`를 그 크기(cm)로 바꿔요.

아직 없는 것(다음 단계): 건물 가림(3단계), 태블릿 간 바리케이드 공유. 마커 지도 만들기는 마커 버전에서 해요.

개발 중 시험 (실제 기기 시험 전):
- 시뮬레이션(2m 디오라마 둘레를 걸으며 비춤, 모서리 잡음·지도 오차·마커 들뜸·ARCore 추적 잡음 포함): 위치 오차 0.3~0.9cm, 방향 오차 0.5° 이하, 맞춤 1.4초
- 가짜 ARCore(WebXR 흉내)로 실제 빌드 시험: 카메라 영상 읽기 → 마커 인식 → 위치 맞춤 → 탭으로 경로 기록 → 주행까지 동작,
  카메라 영상 위아래 방향을 자동으로 찾음(정방향 1.5초, 뒤집힌 경우 2.3초)
- 가짜 ARCore 바리케이드 장면(2단계): 등장 0.4초 뒤 인식, 위치 오차 0.9cm·폭 방향 오차 1°, 바리케이드 앞 간격 0cm에서 정지,
  치운 뒤 2.3초에 재출발

## 6. ARCore 버전에서 할 일 (다음 단계)

지금의 일반 카메라(getUserMedia) + 마커 방식에서 **WebXR(ARCore)** 방식으로 옮길 때 함께 해결할 것들이에요.

먼저 쓸 기기에서 **`/xr-check.html`**(예: `https://mobility-ar.vercel.app/xr-check.html`)을 열어 필요한 기능이 되는지 확인해요.
AR 세션, 카메라 영상 접근(마커·바리케이드 인식), 깊이(건물 가림), 바닥 인식(도로 높이 자동 측정)을 차례로 시험하고 결과를 복사할 수 있어요.

- **가림 처리 (깊이 기반):** WebXR Depth Sensing으로 ARCore가 재는 장면 깊이를 받아, 실제 물체보다 뒤에 있는 AR 차 부분을 그리지 않아요.
  건물·돔뿐 아니라 실제 바리케이드, 사람 손처럼 움직이는 물체도 따로 표시하지 않고 자동으로 가려져요.
  (안드로이드 Chrome + ARCore 깊이 지원 기기 필요. 깊이 지도가 거칠어서 가는 기둥이나 경계는 조금 번질 수 있어요.)
  - 대안(마커 방식에서도 가능): 건물 바닥 모서리를 탭하고 높이를 맞춰 보이지 않는 '가림 상자'를 놓는 방법. 지금은 하지 않기로 했어요.
- **마커를 놓쳐도 유지:** ARCore가 카메라 움직임을 계속 추적하니, 마커는 처음 위치 맞출 때만 필요해요.
- **바닥 기울기 안정:** ARCore가 찾은 바닥 평면과 중력 방향을 쓰면, 마커가 1개만 보여도 바닥이 들려 보이지 않아요.

### 개발 중 시험 결과 (합성 카메라 영상)

- 카메라 위치 오차 0.03~0.18cm, 각도 오차 0.2° 이하
- 바리케이드 위치 오차 0.05~0.5cm, 방향 오차 1° 이하 (검출 모서리 편향 보정 후)
- 마커 지도: 2m×1m 가상 디오라마 테두리에 10cm 마커 10개를 제각각 방향으로 붙이고 한 바퀴 촬영
  → 모든 마커 위치 오차 0.4cm 이하, 방향 오차 0.5° 이하, 초점거리 자동 보정 오차 0.7% (실제 빌드, 헤드리스 Chrome)
- A4 시트: 바리케이드 등장 약 0.6초 뒤 인식 → 감속 → 정지 → 제거 2초 뒤 재출발, 경로 기록 탭 위치 오차 0.1cm 이하
- 차 흔들림(v0.3): 곡선은 촘촘히·직선은 듬성듬성 탭하면 이전 경로 계산(균일 Catmull-Rom)이 곡선과 직선이 만나는 곳에
  작은 고리를 만들어 차가 한 프레임에 최대 177° 돌았어요. 구심 Catmull-Rom + 경로 다듬기 + 앞뒤 바퀴 방향으로 바꾼 뒤 최대 0.5°.
- 바닥 기울기 뒤집힘(v0.3.1): 마커가 1개만 보이면 기울기가 서로 다른 두 자세가 거의 똑같이 맞아서, 이전에는 잡음에 따라
  엉뚱한 쪽(바닥이 위로 들린 모습)을 골라 차가 화면에서 수십~수백 px 튀었어요. 이제 두 자세를 모두 계산해 직전 프레임과 이어지는 쪽을 골라요.
  가상 2m 디오라마 세 곳 × 보는 위치 세 곳 시험: 5° 넘게 틀어진 프레임 최대 33% → 0%,
  최악의 경우 기울기 오차 81.7° → 1.5°, 차 위치 오차 100px → 22px.
- 차선 맞추기(v0.3, 가상 2차로 디오라마, 차선 폭 8cm, 탭 16개에 ±3cm 오차): 차선 가운데에서 벗어난 정도 평균 1.36cm → 0.31cm.
  A4 시트 실제 빌드 시험: 탭 범위 -0.62~0.40cm → -0.20~0.08cm.
- 실제 태블릿 카메라(초점 흐림, 조명, 손떨림)로는 아직 시험 전이에요.
