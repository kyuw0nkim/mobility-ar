# RAIM AR 자율주행 · 마커 버전 프로토타입 v0.2

AI 없이 마커만으로 "도로 정렬 → AR 주행 → 바리케이드 인식 → 감속·정지" 전체 흐름을 확인하는 웹앱이에요.
WebXR·ARCore 없이 일반 카메라(getUserMedia)로 동작하므로 갤럭시 태블릿 Chrome뿐 아니라 노트북에서도 시험할 수 있어요.

## 들어 있는 것

| 파일 | 내용 |
| --- | --- |
| `index.html` | 앱 전체 (단일 파일, 외부 인터넷 필요 없음) |
| `RAIM-AR-마커-10cm.pdf` | 디오라마용 도로 마커 14개: 0~9, 12~15번(10cm, 한 장에 1개) + 바리케이드 마커 10·11(3cm), 15쪽 |
| `RAIM-AR-마커-10cm-추가.pdf` | 0~5번을 이미 인쇄한 경우 추가분: 6~9, 12~15번 (8쪽) |
| `RAIM-AR-테스트시트.pdf` | 1쪽: A4 도로 시트(도로 마커 0~5), 2쪽: 미니 바리케이드 접이식 도안(마커 10·11) |
| `raim-ar-marker-src.zip` | 소스 코드, 빌드·시험 스크립트 |

## 1. 태블릿에서 여는 방법 (HTTPS 필요)

카메라는 HTTPS 주소에서만 열려요. 파일을 태블릿에서 바로 열면 카메라가 막혀요.

- **Vercel (권장):** 이 저장소 폴더에서 `npx vercel` 실행 → 나온 주소를 태블릿 Chrome에서 열기
- GitHub Pages 등 HTTPS 정적 호스팅이면 어디든 돼요.
- 노트북에서 시험: 같은 폴더에서 `python3 -m http.server` 실행 후 `http://localhost:8000` (localhost는 예외로 카메라 허용)

## 2. 책상에서 시험하기 (A4 테스트 시트)

1. PDF 1쪽을 **실제 크기(100%)**로 인쇄하고, 가운데 선이 정확히 10cm인지 자로 확인해요.
2. 시트를 평평한 책상에 테이프로 고정해요.
3. PDF 2쪽을 인쇄해 미니 바리케이드를 접어 세워요.
4. 앱에서 **카메라 시작** → 시트를 **비스듬히** 비춰요. 처음 몇 초간 카메라 화각을 자동 보정해요(왼쪽 위 `f … (보정 n/20)`).
   정면 위에서 수직으로만 비추면 보정이 잘 안 돼요.
5. 빨간 자동차가 도로를 돌기 시작하면, 바리케이드를 도로를 가로지르게 세워요.
   → 인식 카드에 "바리케이드 보임", 판단 카드에 "경로 위 · 앞 n cm", 제어 카드가 감속 → 정지로 바뀌어요.
6. 바리케이드를 치우면, 그 자리가 화면에 보이는 상태로 2초가 지나면 해제되고 다시 출발해요.
   (화면 밖에 있으면 "기억 중"으로 유지해요. 바로 해제하려면 **바리케이드 해제** 버튼.)

## 3. 디오라마에 적용하기 (줄자 필요 없음)

1. **마커 붙이기:** `RAIM-AR-마커-10cm.pdf`의 도로 마커(0~9, 12~15번)를 디오라마 테두리에 붙여요. 세로 변에 4개씩, 가로 변에 3개씩이 기준이에요.
   10·11번은 바리케이드 전용이라 도로에 붙이면 안 돼요.
   위치·방향은 자유예요. 다만 **이웃한 마커 두 개가 태블릿 화면에 함께 들어올 만한 간격**(대략 40~60cm)으로,
   **도로면과 같은 높이에 평평하게** 붙여요. 흰 테두리는 자르지 말고 남겨 두세요.
2. **마커 지도 만들기:** 앱의 **마커 지도 만들기** → 마커 크기 `10` 확인 → 테두리를 따라 천천히 한 바퀴 비춰요.
   - 화면의 마커 색: 파랑 = 기준(원점), 초록 = 등록됨, 주황 = 확인 중
   - 이웃한 마커가 늘 두 개 이상 보이게 하고, 마지막에 처음 마커까지 돌아오면 가장 정확해요.
   - 모두 초록이 되면 **완료·계산**. 1초 정도 계산한 뒤 "정확도 좋음/보통/낮음"을 알려 줘요.
   - 이때 카메라 화각도 함께 보정되고, 자동차 크기·속도도 마커 크기에 맞춰 커져요(3cm → 10cm면 약 3.3배).
3. **경로 기록:** 지도 저장 후 바로 경로 기록 화면이 열려요. 차선 위를 차례로 탭(곡선은 촘촘히) → **완료·저장**.
4. **바리케이드:** 마커 10을 레고 바리케이드 패널 앞면 가운데에, 11을 뒷면 가운데에 붙이고(화살표가 하늘 쪽),
   설정에서 `barricade.width`를 바리케이드가 바닥에서 도로를 막는 실제 폭(cm)으로 바꿔요.
5. 차 크기·속도는 설정의 `car`, `drive`에서 조절해요 (단위 cm, cm/s).

마커를 떼었다 다시 붙이거나 옮기면 **마커 지도 만들기 → 경로 기록**을 다시 하면 돼요.
설정은 그 태블릿의 브라우저에만 저장돼요. 다른 태블릿에는 설정 JSON을 복사해 붙여 넣으세요.

## 4. 현재 한계 (다음 단계에서 해결)

- 도로 마커가 **하나 이상 화면에 보여야** 자동차가 표시돼요. 마커를 놓치면 0.7초 뒤 숨겨요. (ARCore 버전에서 해결)
- 도로 마커는 한 평면 위에 있어야 해요. 낮은 각도용 세운 마커는 아직 안 돼요.
- 돔·건물·실제 바리케이드에 AR 차가 가려지는 처리(가림 처리)가 없어요.
- 태블릿 간 바리케이드 공유("모두 멈춤")는 아직 없어요. 지금은 각 태블릿이 자기가 본 바리케이드에만 반응해요.
- 옆에서 끝면을 보면 바리케이드 마커가 안 보여 인식이 안 돼요.

## 5. 개발

```
npm install
node build.mjs                 # dist/index.html 생성
node tools/make-sheet.mjs      # 테스트 시트 SVG 생성 (rsvg-convert로 PDF 변환)
node test/pipeline.mjs         # 합성 영상으로 자세·바리케이드 정확도 시험
node test/logic.mjs            # 정지 판단·추적 로직 시험
node test/mapping.mjs          # 2m 가상 디오라마로 마커 지도 정확도 시험
```

| 파일 | 역할 |
| --- | --- |
| `src/geometry.js` | 호모그래피, 카메라 자세 계산·보정, 좌표 변환 |
| `src/tracking.js` | 프레임별 도로 자세, 바리케이드 위치 계산 |
| `src/mapping.js` | 마커 지도 만들기 (실시간 추정 + 완료 시 번들 조정) |
| `src/logic.js` | 경로, 정지 판단, 감속 제어, 바리케이드 추적(등장 확인·해제) |
| `src/app.js` | 카메라, 3D 렌더링(Three.js), 인식–판단–제어 화면, 경로 기록, 설정 |
| `src/config.js` | 기본 설정 (A4 테스트 시트 기준) |

마커 인식: [js-aruco2](https://github.com/damianofalcioni/js-aruco2) (MIT), 사전 ARUCO_MIP_36h12. 3D: Three.js (MIT).

### 개발 중 시험 결과 (합성 카메라 영상)

- 카메라 위치 오차 0.03~0.18cm, 각도 오차 0.2° 이하
- 바리케이드 위치 오차 0.05~0.5cm, 방향 오차 1° 이하 (검출 모서리 편향 보정 후)
- 마커 지도: 2m×1m 가상 디오라마 테두리에 10cm 마커 10개를 제각각 방향으로 붙이고 한 바퀴 촬영
  → 모든 마커 위치 오차 0.4cm 이하, 방향 오차 0.5° 이하, 초점거리 자동 보정 오차 0.7% (실제 빌드, 헤드리스 Chrome)
- A4 시트: 바리케이드 등장 약 0.6초 뒤 인식 → 감속 → 정지 → 제거 2초 뒤 재출발, 경로 기록 탭 위치 오차 0.1cm 이하
- 실제 태블릿 카메라(초점 흐림, 조명, 손떨림)로는 아직 시험 전이에요.
