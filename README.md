# RAIM AR 자율주행 · 마커 버전 v0.3.5 + AR(ARCore) 버전 2단계

AI 없이 마커만으로 "도로 정렬 → AR 주행 → 바리케이드 인식 → 감속·정지" 전체 흐름을 확인하는 웹앱이에요.
WebXR·ARCore 없이 일반 카메라(getUserMedia)로 동작하므로 갤럭시 태블릿 Chrome뿐 아니라 노트북에서도 시험할 수 있어요.

## 관람 모드와 관리자 모드

두 버전(AR = `index.html`, 마커 = `marker.html`) 모두 **처음에는 관람 모드**로 열려요.

- **관람 모드:** 시작 화면에는 제목 **도로 위의 상상**과 그 밑의 큰 **[시작하기]** 버튼뿐이에요.
  AR 버전은 [시작하기] → **도안 스캔 → 내 차 미리보기 → [이 차로 달리기]** 순서예요(아래 '나만의 차'). 마커 버전은 누르면 바로 카메라가 시작돼요.
  디오라마 가장자리의 표식을 비추면 저장된 경로로 차가 달려요.
  화면에는 안내 문구, 인식·판단·제어 카드, [위치 다시 맞추기]·[끝내기]만 보여요. 지도·경로·차 설정은 바꿀 수 없어요.
- **관리자 모드:** 화면 오른쪽 위 **⚙(설정)** → 암호 **4300** → 지금까지의 모든 조정 기능(지도 만들기, 경로 기록, 차 크기·속도, 도로 높이,
  전시 설정 내보내기 등)과 디버그 정보가 나와요. 시작 화면과 AR 화면 어디서든 들어갈 수 있어요.
  - 나가기: [관람 모드로] 또는 관리자 모드에서 ⚙를 한 번 더. 새로 고침해도, 10분 동안 아무것도 누르지 않아도(경로 기록·지도 만들기 중은 제외) 관람 모드로 돌아가요.
  - 관람 모드로 바꾸면 하던 경로 기록·지도 만들기는 취소돼요.
  - 암호는 관람객이 실수로 설정을 바꾸지 않게 하는 잠금이에요(웹 페이지 소스를 보면 알 수 있어 보안 장치는 아니에요).
- 화면 디자인은 Autonomous Mobility Tour(같은 교육장 셀프 가이드 앱)와 같은 색·글꼴·유리 패널을 써요.

## 나만의 차 (도안 스캔, AR 버전)

도안: `RAIM-AR-차도안.pdf` (A4 세로 6쪽) — **PBV · 로보택시 · 배송 트럭** 마다 두 장씩이에요.
① 겉모습(내 차 이름, 오른쪽·왼쪽 옆면) · ② 앞·뒤와 실내(앞모습·뒷모습, 지붕 색 고르기, 실내를 위에서 본 모습, 누구를 위한 차인지).
쪽마다 네 귀퉁이의 표식 번호가 달라서(PBV 200~207, 로보택시 208~215, 배송 트럭 224~231) 앱이 어느 차의 몇 쪽인지 알아서 알아봐요.

1. 관람객이 두 장을 색칠하고 꾸며요. 차 이름은 ①의 '내 차 이름' 칸에 크고 진하게, 지붕 색은 ②에서 하나에 ✓. **네 귀퉁이의 검은 무늬는 가리지 않아요.**
2. **[시작하기]** → 카메라로 도안을 비춰요. **아무 장이나 먼저** 비춰도 돼요. 무늬 4개가 잠깐 흔들리지 않으면 저절로 찍히고(3개만 보여도 [찍기]),
   위에 "✓ ① 겉모습 / ② 앞·뒤와 실내 / 로보택시"처럼 찍은 장이 표시돼요. 그다음 남은 장을 비추면 돼요.
   - 한 장만으로 하려면 **[이 장만으로 만들기]** (나머지 쪽은 빈 도안 그림). 그리기 없이 하려면 처음에 **[기본 차로 달리기]**(빈 로보택시).
   - 다른 차의 도안을 비추면 그 차로 새로 시작해요. 카메라를 못 쓰면 **[사진 고르기]**.
3. **미리보기:** 두 장을 편 그림과 3D 차가 돌아가며 보여요. **[안쪽 보기]** → 지붕이 사라지고 실내 그림이 보여요. **[다시 찍기]**, **[이 차로 달리기]** → AR.
4. **AR에서 가까이 가면 실내:** 멀리서는 지붕까지 있는 차, 태블릿을 차에 가까이 가져가면 창문 아래 높이부터 위(지붕·창문·로보택시 센서)가 서서히 사라지고
   ② 실내(배송 트럭은 짐칸) 그림이 바닥에 보여요. 멀어지면 다시 닫혀요.
   - 열리기 시작하는 거리: 차 길이의 약 3.7배(최소 약 37cm), 다 열리는 거리: 차 길이의 2.2배(최소 25cm). 차 크기(차 −/+)를 바꾸면 같이 바뀌어요.
   - 직접 정하려면 설정의 `car.peekNear`(다 열림)·`car.peekFar`(열리기 시작)에 m 단위로 적어요(예: 0.3, 0.5).
5. [끝내기]를 누르면 처음 화면으로 돌아가고, 찍은 도안은 지워져요(다음 관람객은 새 도안으로).

3D 차는 이렇게 만들어요:
- 몸체 = 옆모습 실루엣을 차 폭만큼 밀어 낸 모양(가장자리 둥글게). 폭은 앞모습의 가로·세로 비율로 정해요.
- 옆면 = 오른쪽/왼쪽 옆면 그림, 앞·뒤 면 = 앞모습/뒷모습 그림, 지붕 윗면 = 고른 지붕 색(✓ 없으면 PBV 남색, 로보택시 노랑, 배송 트럭 초록 앞칸).
- 창문(칠하지 않는 곳)은 어두운 유리색으로, '여기에 자유롭게 그려요'·'짐칸 문' 같은 연한 안내 글씨는 주변 색으로 지워요.
- '내 차 이름' 칸에 쓴 글씨만 뽑아 양옆의 '차 이름이 들어갈 자리'에 넣어요(연한 '크고 진하게 써요'는 빼요).
- 바퀴·로보택시 지붕 센서는 따로 붙인 3D, 멈추면 뒤쪽 브레이크등이 빨갛게 켜져요.
- 찍을 때 종이 흰색·무늬 검정을 기준으로 조명 색을 보정해요(누런 조명·비스듬히 찍은 시험 사진에서 칠한 색이 그대로 나옴). 그림은 기기 안에서만 처리하고 어디에도 올리지 않아요.

도안을 고치면: `cd dev && node tools/extract-car-templates.mjs ../RAIM-AR-차도안.pdf` (pdftocairo·pdftotext·pdftoppm 필요)
→ `src/car-templates.js`(치수)와 `assets/car-*.png`(빈 도안 그림)가 다시 만들어져요 → `npm run publish-site`.
칸의 색(남색 지붕 띠, 하늘색 창문, 회색 아래 띠, 점선 이름 칸 등)과 배치로 자리를 찾으니, 같은 디자인 규칙을 지키면 모양을 바꿔도 돼요.

## 1. 태블릿에서 여는 방법 (HTTPS 필요)

카메라는 HTTPS 주소에서만 열려요. 파일을 태블릿에서 바로 열면 카메라가 막혀요.

- **Vercel (권장):** 이 저장소 폴더에서 `npx vercel` 실행 → 나온 주소를 태블릿 Chrome에서 열기
- GitHub Pages 등 HTTPS 정적 호스팅이면 어디든 돼요.
- 노트북에서 시험: 같은 폴더에서 `python3 -m http.server` 실행 후 `http://localhost:8000` (localhost는 예외로 카메라 허용)

## 2. 책상에서 시험하기 (A4 테스트 시트)

1. PDF 1쪽을 **실제 크기(100%)**로 인쇄하고, 가운데 선이 정확히 10cm인지 자로 확인해요.
2. 시트를 평평한 책상에 테이프로 고정해요.
3. PDF 2쪽을 인쇄해 미니 바리케이드를 접어 세워요.
4. 앱에서 **카메라 시작** → 시트를 **비스듬히** 비춰요. 처음 몇 초간 카메라 화각을 자동 보정해요(왼쪽 위 `f … (보정 n/20)`).
   정면 위에서 수직으로만 비추면 보정이 잘 안 돼요.
5. 빨간 자동차가 도로를 돌기 시작하면, 바리케이드를 도로를 가로지르게 세워요.
   → 인식 카드에 "바리케이드 보임", 판단 카드에 "경로 위 · 앞 n cm", 제어 카드가 감속 → 정지로 바뀌어요.
6. 바리케이드를 치우면, 그 자리가 화면에 보이는 상태로 2초가 지나면 해제되고 다시 출발해요.
   (화면 밖에 있으면 "기억 중"으로 유지해요. 바로 해제하려면 **바리케이드 해제** 버튼.)

## 3. 디오라마에 적용하기 (줄자 필요 없음)

1. **마커 붙이기:** `RAIM-AR-마커-8cm.pdf`의 도로 마커(0~9, 12~19번)를 디오라마 테두리에 붙여요. **가로 변에 4개씩, 세로 변에 5개씩(모두 18개)**이 기준이에요.
   10·11번은 바리케이드 전용이라 도로에 붙이면 안 돼요.
   위치·방향은 자유예요. 다만 **이웃한 마커 두 개가 태블릿 화면에 함께 들어올 만한 간격**(대략 40~60cm)으로,
   **도로면과 같은 높이에 평평하게** 붙여요. 흰 테두리는 자르지 말고 남겨 두세요.
2. **마커 지도 만들기:** 앱의 **마커 지도 만들기** → 마커 크기 `8` 확인 → 테두리를 따라 천천히 한 바퀴 비춰요.
   - 화면의 마커 색: 파랑 = 기준(원점), 초록 = 등록됨, 주황 = 확인 중
   - 이웃한 마커가 늘 두 개 이상 보이게 하고, 마지막에 처음 마커까지 돌아오면 가장 정확해요.
   - 모두 초록이 되면 **완료·계산**. 1초 정도 계산한 뒤 "정확도 좋음/보통/낮음"을 알려 줘요.
   - 이때 카메라 화각도 함께 보정돼요. A4 테스트 시트에서 처음 넘어올 때만 자동차 크기·속도를 마커 크기 비율로 키워요(3cm → 8cm면 약 2.7배).
     이미 디오라마 지도가 있으면(예: 10cm → 8cm로 다시 만들기) 맞춰 둔 차 크기·속도는 그대로 둬요.
3. **경로 기록:** 지도 저장 후 바로 경로 기록 화면이 열려요. (AR 버전도 같은 방법, 5장 3번)
   - 화면 가운데 **조준점(+)**을 차가 달릴 곳(흰 중앙선)에 맞추고 화면 아무 데나 탭해요. 진행 방향대로, 직선은 30~50cm, 곡선은 10~15cm마다.
     손가락 위치는 상관없어요(손가락으로 찍으면 화면에서 2~3mm만 빗나가도 디오라마에서는 몇 cm가 돼요). **조준점 끔**이면 예전처럼 손가락 위치.
   - 찍을 때마다 근처의 흰 중앙선에 바로 붙여요: 초록 점 = 붙음, 주황 점 = 못 찾아서 찍은 자리 그대로.
   - 탭하면서 태블릿을 경로를 따라 천천히 움직여 주세요. 이때 보이는 도로를 위에서 본 영상으로 모아요(중앙선 찾기에 써요).
   - **중앙선 맞추기**(초록 버튼) → 찍은 점 사이 곡선까지 흰 중앙선에 붙인 초록 선이 나와요. 주황 구간은 중앙선을 못 봐서 이어 붙인 곳.
     흰 중앙선이 없는 도로(A4 시트 등)면 예전처럼 양쪽 흰 선 사이(어두운 노면)의 가운데로 옮겨요.
   - 초록 선이 괜찮으면 **완료·저장**. 마음에 안 들면 **되돌리기**(초록 선만 지움) 후 탭을 고치고 다시 맞춰요.
   - "덜 비췄어요"가 나오면 탭한 곳을 따라 한 번 더 천천히 비춘 뒤 다시 눌러요.
   - 차선 폭은 영상에서 자동으로 재요. 잘 안 맞으면 설정의 `lane.width`에 실제 차선 폭(cm, 흰 선 안쪽끼리)을 적어요.
4. **바리케이드:** 마커 10을 레고 바리케이드 패널 앞면 가운데에, 11을 뒷면 가운데에 붙이고(화살표가 하늘 쪽),
   기본값은 전시용 레고 바리케이드(전체 폭 17 × 높이 11cm, 노랑·검정 줄무늬 패널 12 × 6cm)에 맞춰져 있어요.
   다른 바리케이드를 쓰면 설정의 `barricade.width`(바닥에서 도로를 막는 폭)·`height`를 실제 값(cm)으로 바꿔요.
   A4 시트의 종이 바리케이드로 시험할 때는 `width` 10, `height` 5.5, `colorHeight`·`colorPanelHeight`는 `null`.
5. 차 크기는 오른쪽 **차 − / 차 +** 버튼으로 바로 조절해요(누를 때마다 1.25배, 설정의 `car.scale`에 저장).
   속도는 **속도 − / 속도 +** 버튼으로 조절해요(누를 때마다 1.25배, `drive.speedScale`에 저장).
   빨라져도 감속 시작 거리와 감속도를 같은 비율로 늘려서 바리케이드 앞에서 똑같이 멈춰요.
   기본값 자체는 설정의 `drive`에서 바꿀 수 있어요 (단위 cm, cm/s).
6. **도로 높이:** 마커를 붙인 면과 도로 면 높이가 다르면(예: 마커는 테이블, 도로는 레고 판 위) 차가 떠 보이거나 파묻혀 보이고,
   휴대폰을 움직이면 차가 도로 위에서 미끄러지듯 따라와요. **높이 − / 높이 +**로 맞춰요(한 번에 마커 크기의 1/40, 8cm 마커면 0.2cm).
   - 차가 떠 보이면 −, 파묻혀 보이면 + 쪽이에요. 자로 잰 높이 차이에서 시작하면 빨라요.
   - 맞추는 법: 휴대폰을 좌우로 움직여 봐서 **파란 경로선이 차선에서 미끄러지지 않고 붙어 있으면** 맞은 거예요.
   - 경로 탭과 차선 맞추기도 이 높이의 면을 기준으로 계산해요. 높이를 바꾸기 전에 기록한 경로는 조금 어긋날 수 있으니 **경로 기록을 다시** 해 주세요.

마커를 떼었다 다시 붙이거나 옮기면 **마커 지도 만들기 → 경로 기록**을 다시 하면 돼요.
설정은 그 태블릿의 브라우저에만 저장돼요. 여러 태블릿이 같은 지도·경로를 쓰려면 아래처럼 전시 설정을 올려요.

### 여러 태블릿이 같은 경로 쓰기 (전시 설정)

마커 지도와 경로는 "디오라마 기준 좌표"라서, 한 기기에서 만든 것을 다른 기기에 그대로 쓸 수 있어요.

1. 한 기기에서 **마커 지도 만들기 → 경로 기록(차선 맞추기)**까지 마치고, 차 크기·속도·도로 높이도 맞춰요.
2. **전시 설정 내보내기**를 눌러 `diorama.json`을 받아요. (마커 버전: 설정 화면 / AR 버전: 시작 화면)
3. 이 파일을 저장소 맨 위 폴더에 올려요(GitHub 웹에서 *Add file → Upload files*, 또는 Claude에게 파일 내용을 보내 올려 달라고 하기). Vercel이 다시 배포하면 끝.
4. 모든 기기가 앱을 열 때 자동으로 불러와요. 시작 화면에 "전시 설정(날짜 저장)을 불러왔어요"가 떠요.

- 같은 파일이면 한 번만 불러와요. 그 뒤 기기에서 바꾼 값(예: 차 크기)은 유지되고, **새 파일을 올리면** 모든 기기가 다시 새 값으로 바뀌어요.
- 기기에서 바꾼 값을 버리고 파일 값으로 되돌리려면 **전시 설정 다시 불러오기**.
- 공유하는 것: 마커 지도, 경로, 도로 높이, 차 크기·속도, 바리케이드 폭, 차선 설정. 공유하지 않는 것: 마커 버전의 카메라 화각 보정값(기기마다 카메라가 달라서).
- 마커를 옮기거나 다시 붙이면 지도·경로를 다시 만들고 `diorama.json`도 다시 올려야 해요.

## 4. 현재 한계 (다음 단계에서 해결)

- 마커가 **하나만** 보이면 바닥 기울기가 덜 정확해요(작은 사각형 하나로는 기울기가 잘 정해지지 않음). 가능하면 **2개 이상** 보이게 비춰 주세요.
  화면 위 문구가 "마커가 2개 이상 보이면 더 안정적이에요"로 알려 줘요.
- 휴대폰을 세로로 들면 인식·판단·제어 카드가 한 줄로 작게, 버튼은 그 아래 3열로 나와요. **메뉴 접기**로 버튼을 숨기고 화면을 넓게 쓸 수 있어요.
- 도로 마커가 **하나 이상 화면에 보여야** 자동차가 표시돼요. 마커를 놓치면 0.7초 뒤 숨겨요. (ARCore 버전에서 해결)
- 도로 마커는 한 평면 위에 있어야 해요. 낮은 각도용 세운 마커는 아직 안 돼요.
- 돔·건물·실제 바리케이드에 AR 차가 가려지는 처리(가림 처리)는 AR 버전에만 있어요(5장 '가림 처리'). 마커 버전에는 없어요.
- 태블릿 간 바리케이드 공유("모두 멈춤")는 아직 없어요. 지금은 각 태블릿이 자기가 본 바리케이드에만 반응해요.
- 옆에서 끝면을 보면 바리케이드 마커가 안 보여 인식이 안 돼요.
- 차선 맞추기는 "어두운 노면 + 흰 선" 도로를 기준으로 해요. 노면과 선의 밝기 차이가 작거나, 선이 아주 가늘어 화면에서 1픽셀도 안 되면
  (예: A4 시트의 0.8mm 점선) 그 선은 못 보고 도로 전체 폭의 가운데로 맞춰요.
- 탭한 경로가 곡선에서 차선 폭의 절반 넘게 옆 차선으로 들어가면 그 구간은 옆 차선에 맞춰질 수 있어요. 곡선은 2~3번 탭해 주세요.

## 5. AR(ARCore) 버전 사용법 — 1·2단계

갤럭시 휴대폰·태블릿의 **Chrome**에서 사이트 첫 화면(`mobility-ar.vercel.app`)을 열어요(마커 버전 시작 화면의 **AR 버전 열기** 버튼도 같은 곳). 아이패드·노트북은 마커 버전을 써요.
마커 지도·경로·차 크기·속도·도로 높이 설정은 **같은 기기의 마커 버전과 함께** 써요.

0. **(실험) 한 바퀴 설치 — 지도와 경로를 한 번에.** 흰 중앙선이 있는 고리 도로 하나를 따라 달리는 디오라마용이에요.
   현장 시험에서 경로가 잘 안 맞았어요. 그럴 땐 [지도 만들기](1번) 뒤 **조준점 탭으로 경로 기록**(3번)을 써 주세요.
   - 준비: 도로 마커(8cm) **4~6개**를 테이블 테두리 흰 바닥(도로 바로 바깥이면 좋아요)에 붙여요. 위치·방향은 자유, 자로 잴 필요 없어요.
     도로 위의 레고 차·바리케이드는 잠깐 치워 두면 더 잘 찾아요.
   - **AR 시작** → **한 바퀴 설치** → 마커 크기(8)·도로 폭(대충, 기본 24cm) 확인.
   - 태블릿으로 **도로를 비추며 테이블 둘레를 천천히 한 바퀴** 걸어요. **탭·경로 카드·마커 멈춰 비추기 모두 없어요.**
     마커는 화면에 들어오면 저절로 등록돼요(마커 근처에서는 마커도 화면에 들어오게 살짝 숙여 주세요).
   - 첫 마커가 등록되면 도로 영상을 모으기 시작하고, 3초마다 흰 중앙선 고리를 찾아 보여 줘요:
     하늘색 = 찾는 중, **초록 = 한 바퀴 찾음**, 주황 = 중앙선을 직접 확인 못 하고 이어 붙인 곳(그 도로를 더 비추면 돼요).
     하늘색 사각형은 등록된 마커 자리예요(실제 마커와 겹치면 맞은 것).
   - 위 안내가 "마커 n개 등록 · 한 바퀴 찾음"이 되면 **완료·저장** → 차가 흰 중앙선 위를 달려요.
   - 다른 태블릿과 쓰려면 **끝내기** → 시작 화면(관리자 모드)의 **전시 설정 내보내기** → `diorama.json`을 사이트에 올려요(3장 참고). 다른 태블릿은 마커 하나만 비추면 위치가 맞아요.
   - 중앙선은 "검은 차로 – 흰 줄 – 검은 차로" 무늬로 찾아요. 다른 도로(화살표 도로, 주차장 흰 칸 선)는 이 무늬가 아니라서 헷갈리지 않아요.
   - 가상 전시 디오라마(테이블 480×190cm, 고리 9.8m, 화살표 도로·주차장·게이트·도로 위 레고 차·천장 조명 반사 포함)에서:
     한 바퀴(가짜 ARCore 36초)에 고리를 찾고, 흰 중앙선에서 평균 0.1~0.2cm(최대 1cm), 마커 6개 위치 오차 0.5cm 이하.
     그 설정으로 다른 태블릿이 마커로 위치를 맞춰도 중앙선에서 평균 0.2cm. 도로 폭을 22~45cm로 잘못 넣어도 같은 결과.
1. **(따로 하기) 지도 만들기 (AR 안에서)** — **AR 시작** → **지도 만들기** → 마커 크기(8) 확인 → 테두리의 도로 마커를 **하나씩** 40~60cm 거리에서 1~2초씩 비춰요.
   - 이웃 마커가 같이 보일 필요 없어요. 마커 위에 "확인 중 n/6" → 초록 "등록됨"이 되면 다음 마커로. 처음 등록된 마커가 "기준"(하늘색)이에요.
   - 다 비췄으면 **완료·저장**. 그 자리에서 바로 위치가 맞춰지고 경로 기록 화면으로 넘어가요.
   - 저장 뒤 디오라마를 한 바퀴 둘러보며 **초록 사각형이 실제 마커에 겹치는지** 확인해요. 많이 어긋나면 천천히 다시 만들어요.
   - 마커를 2~4개만 붙여 써도 돼요(예: 태블릿 자리마다 하나). 마커 버전의 [마커 지도 만들기]도 여전히 쓸 수 있어요.
2. **AR 시작** → 카메라 권한 허용 → 디오라마 테두리의 도로 마커를 비춰요. 1~2초면 "위치 맞춤 완료".
   - 화면의 초록 사각형(지도의 마커 위치)이 실제 마커에 겹쳐 보이면 잘 맞은 거예요.
   - 맞춘 뒤에는 **마커가 화면에 없어도 차가 계속 달려요.** 마커를 볼 때마다 위치가 조금씩 더 정확해져요.
   - 디오라마(책상)가 수평이라고 보고, 기울기는 ARCore가 아는 중력 방향을 써요. 그래서 마커가 1개만 보여도 바닥이 들리지 않아요.
3. **경로 기록 (조준점 탭, 권장):** **경로 기록** → 화면 가운데 **조준점(+)**을 흰 중앙선에 맞추고 화면 아무 데나 탭.
   - 진행 방향대로 한 바퀴, 직선은 30~50cm, 곡선은 10~15cm마다. 태블릿을 가까이(40~60cm) 대고 조준하면 더 정확해요.
   - 찍을 때마다 근처(도로 폭의 0.3배, 24cm면 약 7cm 안)의 흰 중앙선에 바로 붙여요. **초록 점** = 붙음, **주황 점** = 못 찾아서 찍은 자리 그대로.
     앞서 찍은 점들로 다음 점이 있을 만한 선을 예상해서, 가로지르는 주차장 칸 선이나 도로 위 흰 기둥이 바닥에 비친 자국에는 붙지 않아요.
   - 한 바퀴 돌면 **중앙선 맞추기** → 점 사이 곡선까지 흰 중앙선에 붙인 초록 선(주황 구간 = 중앙선을 못 봐서 이어 붙인 곳). 괜찮으면 **완료·저장**.
     초록 점이 충분하면 주황 점은 빼고 맞춰요(잘못 조준한 탭이 곡선을 끌고 가지 않게). 흰 중앙선이 없는 도로면 예전 차선 맞추기로.
   - **조준점 끔(손가락)**을 누르면 예전처럼 손가락 위치로 찍어요(붙이기는 그대로).
   - 가상 전시 디오라마(실측 치수: 흰 가장자리 3 + 검은 차로 11 + 중앙선 2 + 검은 차로 11 + 흰 가장자리 3cm)에서:
     탭이 손가락처럼 ±2.5cm(태블릿)·±5cm(휴대폰) 빗나가도, 붙이기 + 중앙선 맞추기 뒤 흰 중앙선에서 평균 0.01~0.02cm (그대로면 1.8cm·4.4cm).
     가짜 ARCore로 걸으며 조준점 탭 44번(중앙선에서 0~12cm 빗나감) → 31개 붙음(8cm 넘게 빗나간 13개는 주황),
     붙은 점은 모두 중앙선에서 0.7cm 안, 저장된 경로 평균 0.3cm·최대 0.6cm. 붙이는 범위는 도로 폭의 0.3배(24cm면 약 7cm) 안이에요.
   - 도로 폭은 설정의 `lane.roadWidth`: 양쪽 검은 차로의 바깥 끝끼리 잰 폭(전시 디오라마 24cm, 흰 가장자리까지는 30cm). 대충이어도 돼요.
     양옆 차로 폭 전체가 진하게 어두운 흰 줄에만 붙어요.
   - A4 테스트 시트 지도에서는 붙이기·중앙선 맞추기가 꺼져요(가운데가 가는 점선이라). 끄려면 설정의 `lane.centerLine`을 `false`로.
   - 다른 방법: **중앙선 한 바퀴**(탭 없이 비춘 영상으로 고리 찾기, 위 0번과 같은 방법), 아래 경로 카드·자동 경로.
   **경로 카드:** `RAIM-AR-경로카드.pdf`를 인쇄해 두꺼운 종이에 붙여요.
   - **경로 기록** → 카드를 차가 달릴 차선의 **가운데**에 평평하게 놓고, 손을 뗀 채 40~60cm 거리에서 비춰요.
   - **1초 그대로 두면 점이 찍혀요**("점 n 찍었어요", 카드 자리에 주황 → 초록 고리). 카드를 다음 자리로 옮겨요.
     곡선은 5~10cm마다, 직선은 20~30cm마다, 차가 갈 방향 순서대로 한 바퀴. 바로 찍으려면 **카드 위치 찍기**.
   - 한 바퀴 돌면 **완료·저장** → **전시 설정 내보내기**로 모든 태블릿에 공유해요. 도로 영상 인식을 쓰지 않아 현장 조명에 영향받지 않아요.
   - 가짜 ARCore 시험: 카드를 6곳에 차례로 두면 점 6개가 찍히고, 자리마다 오차 0.6cm 이하.
4. **경로 기록 (자동 경로, 보조):**
   - **경로 기록** → 도로를 한 바퀴 천천히 비춰요. 위 안내에 비춘 범위(%)가 나와요.
   - 차가 달릴 **차선 위를 두 번 탭**해요: 출발점, 그다음 진행 방향 쪽으로 조금 앞.
   - **자동 경로** → 검은 차선(양옆의 흰 띠·흰 선 사이)의 가운데를 따라 한 바퀴를 찾아 초록 선으로 보여 줘요. 교차로처럼 흰 띠가 끊긴 곳은 그대로 이어 가요.
   - 괜찮으면 **완료·저장**. 중간에 끊기면 주황 선 끝에 빨간 점이 나와요. 그 주변을 더 가까이 비춘 뒤 다시 누르거나,
     예전 방식(차선 가운데를 여러 번 탭 → **차선 맞추기**)으로 해도 돼요.
5. **높이 자동:** 누른 뒤 3초 동안 도로 위를 비스듬히 비추면 ARCore가 찾은 바닥으로 도로 높이를 재요. **높이 −/+**로 손으로 맞출 수도 있어요.
6. 위치가 어긋났다 싶으면 **다시 맞추기**.
7. **바리케이드(2단계):** 마커 10·11을 붙인 바리케이드를 도로에 세우고 비추면 인식 카드에 "바리케이드 보임",
   경로를 막으면 판단 카드에 "경로 위 · 앞 n cm", 제어 카드가 감속 → 정지로 바뀌어요. 화면에는 바리케이드 자리에 상자가 보여요(노랑: 경로 밖, 빨강: 경로를 막음).
   - 치우면, 그 자리가 화면에 보이는 상태로 2초가 지나면 해제되고 다시 출발해요. 화면 밖에 있으면 "기억 중"으로 유지해요. 바로 해제하려면 **바리케이드 해제**.
   - 바리케이드 마커는 3cm라 대략 **60~80cm 안**에서 인식돼요. 더 멀리서 보려면 마커를 크게 인쇄하고 설정의 `barricade.markerSize`를 그 크기(cm)로 바꿔요.
   - **마커 없이도 돼요(색 인식):** 마커가 안 보이면 **노랑·검정 줄무늬**로 찾아요(인식 카드에 "보임(색)"). 노란 조각이 2개 이상 모인 덩어리만 바리케이드로 보니,
     노란 블록 하나 정도로는 헷갈리지 않아요. 어느 방향에서 봐도 되고 마커보다 멀리서도 잡혀요.
     - 전시용 레고 바리케이드 기본값: `width` 17, `height` 11, 줄무늬 패널 가운데 높이 `colorHeight` 8(패널이 바닥에서 약 5~11cm), 패널 세로 `colorPanelHeight` 6.
       다른 바리케이드면 이 값들을 실제 치수(cm)로 바꿔요. `colorHeight`가 `null`이면 `height`의 0.65배로 봐요.
     - 경로 근처에 노랑·검정 줄무늬 물건이 있으면 바리케이드로 볼 수 있어요. 끄려면 `barricade.color`를 `false`로.
     - **인식 표시**를 켜면 화면의 노란 후보마다 상자와 판정이 나와요: 초록 "바리케이드", 회색 "줄무늬 아님(노란 조각 1개)"·"디오라마 밖",
       주황 "크기 안 맞음 ×n"(n이 1보다 훨씬 크면 `barricade.colorPanelHeight`를 키우고, 작으면 줄여요). 잘 안 잡히면 이 화면을 찍어 보내 주세요.
       크기 확인 범위는 `barricade.colorSizeRange`(전시용 세로 줄무늬 바리케이드 `[0.5, 2]`, 체크무늬형이면 `[0.25, 4]`).
     - 실제 바리케이드 사진 3장(가까이·체크무늬형·멀리)에서 바리케이드만 정확히 찾고, 주변의 노란 점(꽃·건물·차)은 무시했어요.
       전시실 전체 사진 2장(노란 의자, 무지개색 태블릿 케이스)에서는 아무것도 바리케이드로 잡지 않았어요.
     - "디오라마 안" 판정은 마커와 저장된 경로를 모두 덮는 범위 + 15cm로 해요(마커를 한두 변에만 붙여도 가운데 바리케이드를 놓치지 않게).
     - 크기 확인: 그 자리에 바리케이드 패널이 있다면 화면에서 보여야 할 크기와 노란 조각 크기를 비교해, 테이블 너머의 노란 의자처럼
       훨씬 큰 물체는 걸러요. 패널 세로 길이는 `barricade.colorPanelHeight`(전시용 6cm, `null`이면 `height × 0.35`)로 봐요.

8. **가림 처리(3단계):** 실제 건물·돔·게이트·바리케이드·사람 손보다 **뒤에 있는 차와 경로선은 그리지 않아요.** 따로 등록할 필요 없이 자동이에요.
   - ARCore 깊이 인식(WebXR Depth Sensing)으로 카메라 앞 물체까지의 거리를 재서, 그보다 멀리 있는 차 부분을 숨겨요.
   - 깊이 지도는 거칠고(보통 160×90칸) 잡음이 있어서, 실제 물체가 **3cm + 거리의 3%** 넘게 확실히 앞에 있을 때만 가려요(도로 위의 차가 도로에 묻히지 않게).
     가장자리는 조금 번질 수 있어요. 값은 설정의 `occlusion.margin`(m)·`occlusion.marginRel`.
   - 관리자 버튼: **[가림 켬/끔]**(이 기기에 저장), **[깊이 보기]**(깊이를 색으로: 가까울수록 빨강, 멀수록 파랑 — 건물 모양대로 색이 나오면 잘 되는 거예요).
     위 디버그 줄에 `가림 켬(깊이 160×90)`처럼 나오면 동작 중, `깊이 인식 미지원`이면 이 기기에서는 가림이 안 돼요.
   - 안드로이드 Chrome + ARCore 깊이 지원 기기가 필요해요. 먼저 `xr-check.html`에서 '깊이'가 되는지 확인해 보세요.
   - 가짜 ARCore 시험: 일부러 만든 깊이(모두 가까이·위쪽 절반만 가까이·모름)로 방향과 켬/끔이 맞는지,
     가상 전시 디오라마의 실제 깊이로 차가 게이트 지붕 아래로 들어갈 때 가려지는지 확인했어요(`test/e2e-ar-occlusion.mjs`).

아직 없는 것(다음 단계): 태블릿 간 바리케이드 공유, 나만의 차(도안 스캔 → 3D 모델).

개발 중 시험 (실제 기기 시험 전):
- 시뮬레이션(2m 디오라마 둘레를 걸으며 비춤, 모서리 잡음·지도 오차·마커 들뜸·ARCore 추적 잡음 포함): 위치 오차 0.3~0.9cm, 방향 오차 0.5° 이하, 맞춤 1.4초
- 가짜 ARCore(WebXR 흉내)로 실제 빌드 시험: 카메라 영상 읽기 → 마커 인식 → 위치 맞춤 → 탭으로 경로 기록 → 주행까지 동작,
  카메라 영상 위아래 방향을 자동으로 찾음(정방향 1.5초, 뒤집힌 경우 2.3초)
- 자동 경로: 실제 전시 디오라마 같은 가상 도로(검은 차선 사이 흰 띠, 교차 도로 2개)에서 두 번 탭으로 한 바퀴를 닫고,
  차선 가운데에서 평균 0.1~0.5cm(탭을 2cm 어긋나게 해도). 가짜 ARCore A4 시트에서 두 번 탭 → 한 바퀴 → 저장 → 주행까지 동작.
  흰 점선 중앙선 도로는 점선이 곡선에서 길게 끊기면 놓칠 수 있어요(그때는 끊긴 곳을 표시).
- 가짜 ARCore 바리케이드 장면(2단계): 등장 0.4초 뒤 인식, 위치 오차 0.9cm·폭 방향 오차 1°, 바리케이드 앞 간격 0cm에서 정지,
  치운 뒤 2.3초에 재출발. 색으로만 찾기(마커 무시): 0.3초 뒤 인식, 위치 오차 0.7cm·폭 방향 오차 11°, 정지·재출발 같음

### AR 지도 만들기의 원리

- ARCore는 휴대폰을 움직이는 동안 휴대폰의 위치·방향을 **하나의 고정된 세계 좌표**(AR을 시작한 자리가 원점, 위쪽은 중력 반대)로 계속 알려 줘요.
- 마커 하나를 비추면, 마커 네 모서리가 화면 어디에 보이는지로 **휴대폰에서 본 마커의 위치·방향**을 계산해요.
  여기에 ARCore가 알려 준 **그 순간의 휴대폰 위치·방향**을 더하면 마커의 **세계 위치**가 나와요.
- 모든 마커가 같은 세계 좌표로 나오니, 서로 같이 보일 필요가 없어요. (마커 버전은 ARCore가 없어서 '두 마커가 같이 보인 장면'으로 둘 사이 관계를 이어 붙였어요.)
- 작은 마커 하나만 보면 기울기가 반대인 두 답이 비슷하게 맞는데, 디오라마 바닥은 수평이니 중력 방향에 가까운 답을 골라요. 기울어진 마커(15° 넘게)는 표본에서 빼요.
- 마커마다 여러 번 본 값 중 **가까이서 본 절반**의 중앙값을 써서 손떨림·잡음에 강해요.
- 처음 등록된 마커를 원점, 그 마커의 오른쪽을 x축으로 하는 수평 도로 좌표계를 만들고, 모든 마커를 그 좌표(x, y, 방향)로 저장해요.
- 한계: ARCore는 오래 걸으면 위치가 조금씩 밀려요(보통 걸은 거리의 1% 안팎). 그래서 **한 바퀴를 천천히 한 번** 도는 게 좋아요.
  시뮬레이션(2m×1m, 8cm 마커 18개): 밀림이 없으면 마커 위치 오차 평균 0.2cm, 걸은 거리의 1%만큼 밀리면 평균 1.4cm.

## 6. ARCore 버전에서 할 일 (다음 단계)

지금의 일반 카메라(getUserMedia) + 마커 방식에서 **WebXR(ARCore)** 방식으로 옮길 때 함께 해결할 것들이에요.

먼저 쓸 기기에서 **`/xr-check.html`**(예: `https://mobility-ar.vercel.app/xr-check.html`)을 열어 필요한 기능이 되는지 확인해요.
AR 세션, 카메라 영상 접근(마커·바리케이드 인식), 깊이(건물 가림), 바닥 인식(도로 높이 자동 측정)을 차례로 시험하고 결과를 복사할 수 있어요.

- **가림 처리 (깊이 기반, AR 버전에 구현됨 — 5장 8번):** WebXR Depth Sensing으로 ARCore가 재는 장면 깊이를 받아, 실제 물체보다 뒤에 있는 AR 차 부분을 그리지 않아요.
  건물·돔뿐 아니라 실제 바리케이드, 사람 손처럼 움직이는 물체도 따로 표시하지 않고 자동으로 가려져요.
  (안드로이드 Chrome + ARCore 깊이 지원 기기 필요. 깊이 지도가 거칠어서 가는 기둥이나 경계는 조금 번질 수 있어요.)
  - 대안(마커 방식에서도 가능): 건물 바닥 모서리를 탭하고 높이를 맞춰 보이지 않는 '가림 상자'를 놓는 방법. 지금은 하지 않기로 했어요.
- **마커를 놓쳐도 유지:** ARCore가 카메라 움직임을 계속 추적하니, 마커는 처음 위치 맞출 때만 필요해요.
- **바닥 기울기 안정:** ARCore가 찾은 바닥 평면과 중력 방향을 쓰면, 마커가 1개만 보여도 바닥이 들려 보이지 않아요.

#### 처리 흐름과 성능

- **AR 버전:** 카메라 영상은 초당 6번, GPU에서 작게 줄여 **기다리지 않고** 읽어요(PBO). 마커 인식·노랑 줄무늬 찾기·경로 기록 중 도로 영상 모으기는
  **별도 스레드(Web Worker)**에서 해서, 그동안에도 차가 끊기지 않고 그려져요. 계산은 영상을 찍은 순간의 휴대폰 자세로 하니 결과가 몇 프레임 늦게 와도 위치가 어긋나지 않아요.
  화면 왼쪽 위 `인식 n ms`는 워커가 한 프레임 처리에 쓴 시간이에요. 워커를 못 띄우는 브라우저면 `(화면 스레드)`가 붙고 예전처럼 화면 스레드에서 처리해요.
- **가벼운 모드 (기본 켬, 보급형 태블릿용):** 갤럭시 탭 A11+ 같은 보급형 태블릿은 카메라 영상 읽기·마커 인식·3D·ARCore 추적·깊이 인식을 한꺼번에 못 버텨
  몇 초 만에 멈출 수 있어요. 가벼운 모드는 이렇게 줄여요:
  - AR 화면 해상도 **0.5배**, 가장자리 다듬기(안티에일리어싱) 끔, 차 재질 단순화(Lambert)
  - 인식 초당 **3번**(위치 맞추기 전에는 6번, 지도·경로 만들 때 4번)
  - **깊이 인식(가림 처리) 안 함**: 건물 뒤로 가도 차가 가려지지 않아요
  - 화면 글 갱신 0.3초마다
  관리자 시작 화면의 **[가벼운 모드 켬/끔]**으로 바꿔요(이 기기에 저장). 주소로도 돼요: `/?lite=0`(끔) / `/?lite=1`(켬).
  가벼운 모드는 두고 가림 처리만 쓰고 싶으면 **[가벼운 모드 가림 켬]**(기본 끔, 다음 AR 시작부터). 이걸로 멈추면 '지난 AR'에
  `깊이 인식 n초` 직후에 멈췄다고 나와요. 고성능 태블릿(갤럭시 탭 S 등)은 가벼운 모드를 꺼도 돼요.
- **지난 AR 기록:** AR이 멈춰서 화면을 못 읽어도, 1초마다 이 기기에 기록을 남겨요. 다시 열면 관리자 시작 화면에 **지난 AR**이 나와요:
  몇 초 동안 켜졌는지, 정상 종료인지 **끝내기 전에 멈춤**인지, 카메라 영상·첫 인식·위치 맞춤·차 보임·깊이 인식이 각각 몇 초에 됐는지,
  마지막 몇 초의 fps·최대 프레임 간격·JS·인식 시간. 멈추기 직전 단계가 원인 후보예요.
- **AR 화면이 버벅이거나 멈칫할 때(가벼움 설정):** AR 화면 해상도는 태블릿 화면의 **0.75배**(`/?fb=1`이면 원래 해상도), 바닥 찾기(hit-test)는 **[높이 자동]으로 잴 때만** 켜요. 가림 처리를 꺼 두면 다음 AR 시작부터 ARCore 깊이 계산도 안 해요.
  카메라 화면 위 글·카드는 **바뀔 때만** 다시 그리고, 큰 흐린 그림자·속도 막대 애니메이션은 AR 중엔 빼요.
  관리자 디버그 줄 끝의 `끊김 n회/5초(최대 ms)`가 100ms 넘게 화면이 멈춘 횟수, `JS n ms`는 프레임마다 이 앱이 쓴 시간이에요.
  JS가 작은데(몇 ms) 끊김이 많으면 기기 GPU·ARCore 쪽(발열·다른 앱) 문제이고, `인식 n ms`가 150ms를 넘으면 인식 스레드가 밀리는 거예요.
- **마커 버전:** 화면은 60~120Hz로 그리지만 카메라는 보통 30fps라, **새 카메라 영상이 왔을 때만** 인식해요(`requestVideoFrameCallback`).
- 두 버전 모두 **차 −/+·높이 −/+**를 눌러도 추적 중인 바리케이드와 차 위치를 그대로 둬요(지도·경로가 바뀔 때만 새로 시작).

### 개발 중 시험 결과 (합성 카메라 영상)

- 카메라 위치 오차 0.03~0.18cm, 각도 오차 0.2° 이하
- 바리케이드 위치 오차 0.05~0.5cm, 방향 오차 1° 이하 (검출 모서리 편향 보정 후)
- 마커 지도: 2m×1m 가상 디오라마 테두리에 10cm 마커 10개를 제각각 방향으로 붙이고 한 바퀴 촬영
  → 모든 마커 위치 오차 0.4cm 이하, 방향 오차 0.5° 이하, 초점거리 자동 보정 오차 0.7% (실제 빌드, 헤드리스 Chrome)
- A4 시트: 바리케이드 등장 약 0.6초 뒤 인식 → 감속 → 정지 → 제거 2초 뒤 재출발, 경로 기록 탭 위치 오차 0.1cm 이하
- 차 흔들림(v0.3): 곡선은 촘촘히·직선은 듬성듬성 탭하면 이전 경로 계산(균일 Catmull-Rom)이 곡선과 직선이 만나는 곳에
  작은 고리를 만들어 차가 한 프레임에 최대 177° 돌았어요. 구심 Catmull-Rom + 경로 다듬기 + 앞뒤 바퀴 방향으로 바꾼 뒤 최대 0.5°.
- 바닥 기울기 뒤집힘(v0.3.1): 마커가 1개만 보이면 기울기가 서로 다른 두 자세가 거의 똑같이 맞아서, 이전에는 잡음에 따라
  엉뚱한 쪽(바닥이 위로 들린 모습)을 골라 차가 화면에서 수십~수백 px 튀었어요. 이제 두 자세를 모두 계산해 직전 프레임과 이어지는 쪽을 골라요.
  가상 2m 디오라마 세 곳 × 보는 위치 세 곳 시험: 5° 넘게 틀어진 프레임 최대 33% → 0%,
  최악의 경우 기울기 오차 81.7° → 1.5°, 차 위치 오차 100px → 22px.
- 차선 맞추기(v0.3, 가상 2차로 디오라마, 차선 폭 8cm, 탭 16개에 ±3cm 오차): 차선 가운데에서 벗어난 정도 평균 1.36cm → 0.31cm.
  A4 시트 실제 빌드 시험: 탭 범위 -0.62~0.40cm → -0.20~0.08cm.
- 실제 태블릿 카메라(초점 흐림, 조명, 손떨림)로는 아직 시험 전이에요.
